# 全流程性能剖析与优化选项（第 21 轮，供决策）

> 背景：圆孔倒角已按用户决定关闭（第 21 轮，方孔/矩形孔保留）。
> 本文记录整条重建管线的分阶段耗时实测，以及剩余的优化选项、预期收益与代价。

## 1. 渲染器现状（已具备的机制）

- **250ms 防抖**：参数连续变化时只重建最后一次；
- **按部件依赖增量重建**：`renderModel` 里 base / lid / seal / DIN / 支柱 / 线缆夹 /
  通风各自有依赖清单（`checkDeps(diff, xxxDeps)`），diff 里没有的部件直接复用旧模型；
- 碰撞检测（`pcbCollision`）在每次 renderModel 都会执行（PCB 预览开启时）。

也就是说「依赖拆分」这条最常见的优化路**已经走过了**，剩余空间在几何计算本身与调度策略。

## 2. 分阶段耗时实测（Node 直连，三次最佳）

### 轻量模型（默认近似：2 个开孔，无 PCB/通风/线缆夹）

| 阶段 | 耗时 |
|---|---|
| base() | 245ms |
| lid() | 362ms |
| 防水密封圈 | 24ms |
| **合计（全部依赖变化时）** | **≈ 630ms** |

### 重量模型（4 开孔 + PCB 预览 + 支柱 + 双面通风 + 线缆夹）

| 阶段 | 耗时 |
|---|---|
| base() | 343ms |
| lid() | 357ms |
| 防水密封圈 | 29ms |
| 通风（两项） | 1ms |
| **pcbCollision（碰撞检测）** | **467ms*** |
| PCB 支柱 / 线缆夹 | 1 / 7ms |
| **合计** | **≈ 1.1~1.2s** |

\* 本表实测把 `base(p)` 作为参数传入（渲染器实际传入已建好的 baseModel，不重复计），
碰撞本身的 intersect 开销估计在 150~250ms 量级，仍是大头。

由于有按部件增量重建，**典型的单参数拖动只重建 1~2 个部件**（如调通风 → base + 通风 ≈ 350ms；
调宽/高/壁厚 → base + lid + seal 全家 ≈ 600ms~1s）。用户感到卡的位置主要在后者。

## 3. 优化选项（按性价比排序）

### D. pcbCollision 节流 / 按需重算 —— ✅ 已实施（第 22 轮）

- 原状：PCB 预览开启时，**每次 renderModel 都重算碰撞**——哪怕这次改的是通风或壁挂；
- 已做：碰撞结果按依赖缓存（`collisionDeps`），无关参数变化时直接复用上次结果；
  依赖变化时先按旧结果渲染，**延迟 300ms 补算**并原位替换 PCB 实体（板体/净空区颜色
  随之刷新）；组件销毁时清理定时器；seq 号防过期结果覆盖；
- 收益：重模型每次重建省 150~250ms 的同步阻塞；代价：小；风险：低
  （警告横幅最多晚 300ms 出现，板体颜色随后刷新）。

### B. 交互期降质 —— ✅ 已实施（第 23 轮）

- 做法：全局段数开关贯穿各模块（圆/槽/锥默认 24/16 段），参数拖动过程中用 12 段快速出模，
  停止变化 250ms 后用正常段数精修一次；
- 收益：拖动过程中的连续反馈提升 2~3 倍（base+lid ≈ 600ms → 200~300ms），
  最终产物不变；代价：中（要给各模块传段数参数）；风险：低（精修兜底）。

### E. lid() 内部热点剖析（中型）

- 实测 lid()（362ms）比 base()（245ms）还贵——内部有嵌入边顶端倒角
  （topChamferTool 的 8 次剪切求交）、clover 框、螺丝孔、卡扣等；
- 做法：对 lid() 内部逐段计时，找出最大热点（疑似嵌入边倒角的 8 次 intersect），
  针对性降段数或合并切割体；
- 收益：中（可能省 100~200ms）；代价：中；风险：低（纯性能不动几何）。

### A. 重建挪进 Web Worker —— ✅ 已完成（第 25~27 轮：A-1/A-2/A-3）

- 做法：JSCAD 几何管线整体搬进 Worker，主线程只发参数、收结果；
- 收益：**重建期间 UI 完全不冻结**（旋转/缩放照常），任何模型都不卡；
- 进度：**A-1 ✅**（buildParts 纯函数 + worker 薄壳 + GeometryBuilder 服务，
  Worker 不可用自动回退同步）；**A-2 ✅**（renderModel 异步化：依赖判断收集部件 →
  worker 构建 → 主线程组装，renderSeq 防过期、destroyed 兜底；Karma 280 全绿，
  含「异步管线产出完整模型」端到端验收）；
  **A-3 ✅**（第 27 轮）：导出面板几何构建也走 builder（STL/STEP 序列化留主线程）；
  Worker 内布尔抛错的错误传播（回传 error → 主线程 rejection → 同步兜底）；
  build() 同步回退路径的抛错也转为 rejection（API 契约：永远返回 Promise）。
  紧凑序列化经评估不做（Geom3 structuredClone 成本仅 ~10ms 级，收益不抵复杂度）。
- 备注：headless Chrome 的 --virtual-time-budget 截图与 Worker 消息不兼容
  （虚拟时间不等 worker 回包，视口永远空白）——这是截图工具限制，
  Karma 真实 Chrome 端到端测试已证明链路正常。

### C. 内容键记忆化（补充性）

- 做法：holes / ventilation / pcbMounts 等数组项按 JSON 内容键缓存切割体；
- 收益：改「与数组无关」的参数时跳过数组重建（但 width/height 等仍会失效）；
  在已有按部件依赖重建的前提下，**边际收益有限**；代价：低。

## 3.5 lid() 热点剖析（第 24 轮，E 项前置分析）

lid() 内部按 lid.ts 装配链分阶段计时（默认参数，合计 ≈620ms）：

| 阶段 | 耗时 | 占比 |
|---|---|---|
| ② 嵌入边 cloverFrame | 165ms | 27% |
| ⑩ 顶倒角工具 topChamferTool（8 向剪切求交） | **157ms** | **25%** |
| ⑨ subtract(底边倒角) | 78ms | 13% |
| ⑪ subtract(顶倒角) | 68ms | 11% |
| ③ union(本体, 嵌入边) | 51ms | 8% |
| ⑦ subtract(本体, 切割体) | 59ms | 10% |
| 其余（本体/螺丝孔/工具构造） | ~45ms | 7% |

两个候选优化的实测收益上限：

| 候选 | 实测 | 风险 |
|---|---|---|
| clover2d 内容键缓存（lid 内构造 2 次同参轮廓） | clover2d 单次仅 **12ms** → 缓存收益 ~12~24ms | 无（纯函数缓存）——**✅ 已实施（第 32 轮）**：实测 lid() 冷缓存 382ms → 命中 374ms（省 ~8ms/次，lid 三次 clover2d 中仅外圈与倒角 slab 同参可复用）；缓存键含段数（交互期/全质量不串线），上限 64 组超限清表 |
| topChamferTool 改 2D 腐蚀（`expand({delta:-c})` + 挤出 + 1 次 subtract，替代 8 次 3D intersect） | **157ms → 57ms（−62%，省 ~90ms）** | **中**：圆盘腐蚀与八边形腐蚀的倒角宽度从「0.92c~1.0c 波动」变均匀，几何有差异，需重跑 verify-rim-chamfer 的 360 箱覆盖断言并重新验收外形 |

结论：E 的现实收益 ≈ **90ms（倒角工具改造）+ ~12ms（缓存）**，且前者有几何变化风险；
布尔链本身（union+3 次 subtract ≈ 256ms）是必要开销，难再压。

## 4. A（Worker 化）专项分析（第 24 轮）

**可行性（基于本库现状）**：
- 几何模块 `core/enclosure/*` 是纯函数、零 Angular 依赖，可直接在 Worker  import；
- `Params` 是纯 JSON；JSCAD `Geom3` = `{polygons, transforms}` 也是纯数据 →
  structuredClone 可直接回传（或转紧凑数组更快，几 MB 级数据序列化 <50ms）；
- 渲染器的部件依赖拆分、250ms 防抖、loading 信号都已就绪，Worker 只需替换
  「同步几何构建」这一段。

**收益**：
- 重建期间 UI **完全不冻结**：拖动参数、旋转、缩放全程响应（精修 300~600ms、
  重量模型全重建 ~1s 都只表现为转圈）；
- 与 B/D 正交叠加（Worker 内同样调 `seg()` 即可）；
- A 落地后 B 的「交互期快模」使命退化（不阻塞就不需要快模），但已实现且无害，保留。

**代价与风险**：
- 工作量 **2~3 轮**：worker 模块 + 消息协议 + 主线程拆分（几何进 worker，
  组装 / entitiesFromSolids / regl 渲染留主线程）+ 错误与超时处理；
- Vite worker 语法（Angular 20 支持 `new Worker(new URL('./geo.worker.ts', import.meta.url), {type:'module'})`）；
- **测试策略**：Karma 对 Worker 支持差 → 必须把「构建管线」抽成纯函数模块
  （现有 `base()/lid()/...` 即是），worker 只做薄壳，单测仍打纯函数；
- 回归面在渲染管线（主线程组装逻辑必须与现有一致）；
- 导出路径（tools.component）可暂不动（仍在主线程算）。
