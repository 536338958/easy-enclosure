# 阶段 1 基线的浏览器验证指南

对应 `docs/baseline-before.txt` 的 10 项 FAIL。上游原版界面是**纯英文**的（i18n 在阶段 7
才搬），下面用英文原标签。

本地起服务：

```bash
npx ng serve --port 4400 --host 127.0.0.1
# → http://127.0.0.1:4400/easy-enclosure
```

**先说结论**：10 项里只有 1 项能在浏览器里直接看到。上游渲染器把盖板摆在底壳**旁边**
（`renderer.component.ts` 的 `SPACING = 20`，第 882 行），不是装配姿态，所以「盖板装不进去」
这类干涉在界面上**根本看不到**；内隔板又在实心底壳内部，也被挡住。

| Bug | 浏览器可见 | 怎么验 |
| --- | --- | --- |
| 1 · 挂耳切角恒 45° | ⚠️ 只能看到"没有滑块" | 参数面板找 Wall Mounts 区 |
| 2 · `floor` 失效 + 隔板落座错 | ✅ **能看** | 见下方「验证 A」，铁证 |
| 3 · 装配干涉 4 项 | ❌ 看不到 | 用导出的 STL，见「验证 C」 |
| 4 · 防水层被打穿 | ✅ **能看** | 见下方「验证 D」 |


## 验证 A · `floor` 参数失效（铁证，30 秒）

这是 Bug 2 的根因，比隔板错位更根本：**关闭盖板螺丝时底板厚度由 `wall` 决定，
`floor` 滑块被完全忽略。**

步骤：

1. **Lid Screws** → 取消勾选（关键，必须关）
2. **Water Proof** → 取消勾选
3. 视角转到能俯视内腔（滚轮拉高、或按住拖动让开口朝向自己）
4. 记下 **Wall** 当前值（默认 2），看一眼内腔深度
5. 把 **Wall** 拖到 **6** → **底板明显变厚，内腔变浅**
6. 再把 **Floor** 从 3 拖到 10 → **底板厚度纹丝不动**

判读：第 5 步变了、第 6 步没变 = `floor` 失效，底板厚度 = `wall`。

实测（逐层体积法，`floor` 固定 3）：

| wall | 1 | 2 | 3 | 4 | 6 |
| --- | --- | --- | --- | --- | --- |
| 实测底板厚 | 1.00 | 2.00 | 3.00 | 4.00 | 6.00 |

根因在 `base.ts` 的两条分支构造内腔的方式不同：

- `lidScrews = true`：`translate([_wall, _wall, floor], clover(…))` → 底板 = `floor` ✅
- `lidScrews = false`：`hollowRoundCube(…)`，内部是 `translate([t, t, t], inner)`，
  **z 也平移了 t** → 底板 = `_wall` ❌

防水时更夸张：`_wall = 2·wall + 2·insertClearance + insertThickness`，
wall=1.5 时底板达 **5.08mm**（用户设的仍是不起作用的 3）。

附带后果（隔板落座错位，被底壳挡住、界面上看不到）：内隔板用裸 `floor`，于是
防水时隔板底部**埋进底板 2.08mm**，非防水时隔板**悬空 1.50mm**。

> 更正：`baseline-before.txt` 初版把这两个方向记反了（写成"防水悬空、非防水陷入"），
> 已改。逐层实测的实测转折点是 1.50 / 3.00 / 5.08，与 `cavityFloorZ` 完全吻合 ——
> 判据是对的，错的是 `internalwalls` 的落座基准。


## 验证 B · 挂耳切角恒 45°

不是回归，是**上游没有这个功能**（角度参数化属于 A4，阶段 3 才搬）。

步骤：勾选 **Wall Mounts** → 看挂耳的斜切角 → 无论怎么调参数都只有 45° 一种，
参数面板里也**没有**角度滑块。

所以这项 FAIL 的判据来自本分支新增的参数，上游原版不可能通过 —— 属于"待移植功能"
而非"缺陷"。


## 验证 C · 装配干涉（界面看不到，用 STL）

四类干涉里界面只能看到盖板孤零零摆在旁边，验证要靠导出件。

已生成装配姿态的 STL 对（盖板按真实装配姿态镜像、嵌入边朝下插入底壳）：

```bash
npm run verify:build && node docs/gen-assembly-check.cjs
# → docs/assembly-check/
```

| 文件对 | 干涉体积 | 现象 |
| --- | --- | --- |
| `A-防水-关螺丝-wall3` | 491 mm³ | 密封圈槽四角与嵌入边对撞，随壁厚线性增长 |
| `B-防水-关螺丝-wall1` | 328 mm³ | 同上，壁更薄时略小 |
| `C-非防水-开螺丝-wall3` | **3757 mm³** | clover 凹弧失配，最严重 |
| `D-非防水-关螺丝-wall3` | 0 | **对照组**，应严丝合缝 |

每对的两个 STL 同时拖进 BambuStudio / 任意 3D 查看器（Z 范围已验证：
底壳 `[0, 30]`、盖板 `[26, 32]`，即嵌入边确实插进去了）。

判读：

- **A / B** —— 看**四个角**：嵌入边的圆角与槽的 clover 让位缺口互相穿插
- **C** —— 干涉最大最明显，沿整圈嵌入边都有，不只是角
- **D** —— 对照，四周应只留一条 0.04mm 的均匀缝

⚠️ 看 A/B 时注意：0.04mm 的设计间隙小于 JSCAD 布尔运算的稳定区间，会随机报假干涉
（如 wall=2 的 59mm³）。**随壁厚连续增长的是真问题，孤立跳变的别当真。**


## 验证 D · 防水层被打穿（防水 + 关螺丝）

与验证 A 一样能在界面上直接看到，因为打穿发生在**内腔四角**，从上方俯视可见。

步骤：

1. **Water Proof** → 勾选
2. **Lid Screws** → **取消勾选**（关键，开了螺丝就不会打穿）
3. **Wall** → 拖到 1.5（其实 1~6 都会，1.5 只是你观察到的那个值）
4. 从**上方俯视**内腔，重点看**四个角**

判读：正常时内腔是一圈完整的壁，外圈的密封圈槽与内腔**不相通**。打穿时能看到
四个角处内腔壁有缺口，内腔与外面那圈槽**连成一片**。

换 **Lid Screws 勾上**再对比一次 —— 四角缺口消失。这个开关对比就是根因的最直观演示：
内腔形状跟着开关变（clover ↔ 圆角矩形），而槽恒为 clover，不同族就打穿。

量化结果（判据 = 密封圈槽与内腔的相交体积）：

| wall | 1 | 1.5 | 2 | 3 | 4 | 5 | 6 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 开螺丝 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 关螺丝 | 361.72 | 353.69 | 347.99 | 339.11 | 329.36 | 315.56 | 294.85 |

打穿体 z ∈ [24.00, 30.04]，正好是槽的整个高度；四角顶点数 310/316/324/324，
即**四个角全穿**。

根治方案已验证有效：把槽改成与内腔同族（圆角矩形），相交体积**全部归零**。
这一条同时消灭 3.1 的 370mm³ 装配干涉，属阶段 4 的 B2，不单独立项。


## 还没修的已知缺陷

C 组那个 3757mm³ 不属于阶段 4 的修复范围：clover 四角是**凹**圆弧，对它做
「长宽减 2t + 平移」并不是等距偏移，凹弧处必然失配。这是 `utils.ts` 里
`cloverFrame2d` 上方 TODO 记录的固有缺陷，**上游与本分支共有**，需要单独立项
（真等距 offset：凹弧半径应是 `r + t` 而不是 `r`）。
